# PokéVerse 長期自動化 — AI 工作規格

專案：https://github.com/borago0219-chatgpt/pokemon-universe-pokedex

## 目標與範圍
非官方粉絲圖鑑，逐步涵蓋全國圖鑑、Pokémon GO、寶可夢主系列遊戲的可取得性、捕捉方式、推薦招式與原創圖像。
**專案已公開的程式碼 ≠ 網站已公開發布。未經使用者確認，不自行在 Cloudflare 或其他平台部署。**

## 每日雙軌流程
1. GitHub Actions 約台灣時間 19:17：執行 `scripts/update_pokedex.py`，從 PokéAPI 新增最多 5 筆基本資料（注意 GitHub 排程可能延遲或跳過，必須檢查執行記錄）。
2. ChatGPT 排程約台灣時間 20:00：依 `automation/progress.json` 的 queue 順序選取最多 2 個新研究任務，重新查核最多 2 筆舊攻略，準備最多 1 份插圖需求。不使用付費圖像 API；如生圖功能不可用，僅放入待辦佇列。
3. 優先處理 `pokemon-go` 和 `scarlet-violet`，待初版完成逐款擴張。涉及當下遊戲活動、可取得性與配招時，必須重新查閱來源，避免把歷史活動當成正在舉行。
4. 建立包含來源 URL、來源類型、訪問日期、遊戲版本、招式類型（GO PvP/團戰、主系列單打/雙打/劇情）及查核狀態的研究紀錄。
5. 經多來源核對的資料可以加入 `data/guides.json`，但僅標成 `draft` 或 `reviewed`，避免未經審核的攻略被顯示為權威內容。若遇爭議，保留 `needs_review`，不臆測。
6. 更新隊列中任務狀態、重試次數、最後查核時間與變更紀錄；每次執行只提交本次變更的檔案，不覆蓋其他人提交的內容。必須先讀取最新 SHA 或建立 PR。
7. 回報已新增/查核/待審的數量與 GitHub 連結；即使無新增也留下簡短原因。

## 嚴謹的資料規則
- 不杜撰捕捉地點、活動有效期間、招式可學性、最佳配招或來源。
- 以官方遊戲公告、官方支援資訊、PokéAPI 為基礎；對配招與環境判斷可補充有聲譽的社群來源，標示「社群建議、非官方」與查核日期。
- `data/pokemon.json` 是 GitHub Actions 專用的基本資料檔；ChatGPT 工作不得修改它，避免合併衝突。
- `data/guides.json` 結構預期為 `{schema_version, updated_at, guides:[]}`。每個項目需含 `key`、`national_id`、`game`、`topic`、`content`、`sources`、`checked_at`、`status`。唯一鍵格式 `<id>:<game>:<topic>`；重跑時依 key 更新，不能新增重複項目。
- 保留資料查核紀錄，不能以網站「沒有出現」就推斷寶可夢不可取得。
- 原創插畫不等於自動取得角色著作權的使用授權；每張圖需有人審核，來源與生成狀態需記錄；不自動冒用官方插圖，也不擅自付費。
- 網站要加入已驗證攻略顯示功能時，先測試再發布；不要讓待審稿直接當成正式攻略。

## 失敗與額度限制
- 每次最多 2 筆新攻略、2 筆重新查核、1 份繪圖簡報；有能力但無額度時仍可完成較少數量。
- API、登入或 GitHub 授權失敗時，記錄 blockers，不重複空轉；無權限時提供可複製的草稿，不宣稱已推送。
- 不要求使用者提供登入密碼或存取權杖；如網站要求驗證，交由使用者自行完成。
- 不宣稱每日 ChatGPT 排程一定能操作 Work 雲端電腦；在任務執行環境無雲端瀏覽器時，優先使用已連接的 GitHub 工具和可公開查證的網頁，並回報工具限制。
- 自動化長期更新不等於 24/7 無限運作；GitHub Actions 或 ChatGPT 排程都可能受額度、延遲、網站限制影響。

## 擴展前須檢查
- 部署/公開分享：需使用者明確確認之後才發布。
- AI 實際生成並提交圖片：需確認可用的圖像工具、授權、儲存方式與額度。
- 更高容量／會員資料庫：先用免費 GitHub 靜態檔案，確實需要再評估。

## 待辦佇列的自動補貨規則
- 每輪先處理既有 `automation/progress.json` 的 pending 工作，不要為了湊量重做 awaiting_review、done 或已完成的相同 `<id>:<game>:<topic>`。
- 當 pending 少於 3 筆時，從目前 `data/pokemon.json` **已存在**的編號選擇尚未建立攻略的下一個寶可夢與遊戲／主題，優先 Pokémon GO 的捕捉、PvE/PvP 配招，以及《朱／紫》的取得方法。補入最多 5 筆 pending 任務，不能把「預定要研究」當成已確認在該遊戲出現。
- 動態建立 task_id 時先檢查 queue、guides 唯一鍵是否已有同項目，確保重跑不產生重複；待辦不是已完成研究，不占每日 2 筆新攻略產出上限。
- 當既有寶可夢都已經建檔且無可補項目時，改進行核實來源的新舊差異、攻略過期檢查、排版品質與人工待審清單，不用虛構工作成果。
- 當前網站尚未接上 guides 的展示功能，因此寫入 draft 不等於網頁已公開新增該攻略；每次進度回報需要區分「已保存研究」和「網頁已顯示」。
